# CLAUDE.md — working on PPPCCC M:C Mods

Firmware mods for the **Elektron Model:Cycles OS 1.13** (also run on a Model:Samples with the Cycles OS). The repository
holds only our own code: generators that write ColdFire machine code, the resulting patch files, tools to build a
firmware from the user's own official file, emulator tests, docs, the project page and a browser flasher.
Personal working rules of the maintainer are in `CLAUDE.local.md` (not in git) — read it first if it exists.

## Hard rules

- **No Elektron code or bytes in the repository or in anything shared.** Hooks are checked by (length, SHA-256) of the
  original bytes. Where a hook moves original instructions into our code, the generator uses `orig VA,N` (cfasm), the
  published patch holds zeros + `from_original`, and the build copies the bytes from the user's file.
- Firmware files never go into git (`*.syx`, `*.bin`, `firmware/`, `build/` are ignored).
- Every patch stays modular: each patch must build alone with only what it `requires` (test_modular checks this).
- A change is done when: generators regenerate it, `src/regen.py` passes, the affected tests and `test_modular` pass, and a
  test build is made. Docs are updated at the end of a feature round, not per experiment.

## Layout

| Path | What |
|---|---|
| `src/v2/` | **The source of truth.** One generator per patch (`g2_*.py`), `gen_all.py` runs them all. Comments are German. |
| `src/v2/cfasm.py`, `cfemac.py` | our ColdFire assembler (text -> bytes, incl. MAC/EMAC); `common.py` = shared addresses, slots, layout |
| `src/*.py` | v1.0.0 generators (reference for some tests) and shared code (effect cores, groove tables) |
| `patches/NN-*.json` | published patches (`len + old_sha256 + new`), `manifest.json` (full set + result checksums) |
| `tools/build.py` | official `.syx` -> modded `.syx` (checks every write, the result and the container) |
| `tools/apply_patches.py` | section-3 image -> patched image; `to_public()` = dev write -> published write |
| `tools/vendor/` | unchanged MIT copies: drumkilla's mtlib/tweak.py, Modded-Cycles' aplib_grow.py/crossflash.py |
| `tests/` | Unicorn emulator tests (`run_all.py`), `check_flasher.mjs` (flasher == build.py) |
| `flasher/` | browser flasher, pure JS port of the build (`lib.js`) |
| `docs/` | user guide, build guide, technical reference, changelog, one page per patch, PDF manual |
| `index.html`, `assets/` | GitHub Pages project page |
| `tools/make_manual.py` | builds the PDF manual from README / USER_GUIDE / docs/patches (needs playwright + chromium) |

The docs in `docs/patches/*.md`, `docs/TECHNICAL.md` and `index.html` were generated by tools that are not in this
repository. From now on edit them by hand.

## First-time setup (macOS)

```sh
python3 -m pip install unicorn capstone numpy pillow scipy   # + playwright pypdf markdown for the manual
git clone https://github.com/18nelli18/Modded-Cycles      # in the repo root: emulator rigs, EMAC emulation, sprite-mask list
mkdir -p firmware                                          # put the official files here (never committed):
#   firmware/model-cycles_OS1.13.syx                      (SHA-256 44fe5862...640c)
#   firmware/model-cycles_OS1.13_for-model-samples.syx    (made with Modded-Cycles' crossflash.py --to samples)
```

Check the setup (all must pass; numbers are from 2026-11-22, release 2.3.1):

```sh
python3 src/regen.py firmware/model-cycles_OS1.13.syx                 # 20 x "ok"
python3 tools/build.py --in firmware/model-cycles_OS1.13_for-model-samples.syx --out build/check
#   -> build/check_cyc-os.syx, sha256 082dc73a04cc5d154ec99916355d1dbf9a2b6084e8c8eef3192225ab1d796c04
python3 tests/run_all.py firmware/model-cycles_OS1.13.syx -j 4        # ends with "all tests ok" (takes a while)
```

The emulator tests were only ever run on Linux. If Unicorn/Capstone behave differently on Apple Silicon, report it
instead of changing the tests.

## Workflow for a change

1. Edit the generator(s) in `src/v2/` (and `common.py` for shared layout).
2. `python3 src/regen.py firmware/model-cycles_OS1.13.syx --write --samples firmware/model-cycles_OS1.13_for-model-samples.syx`
   rewrites `patches/*.json` (writes, hooks, memory, symbols …; name and description stay) and `manifest.json`.
   A new patch file has to be added to `manifest.json` → `patches` by hand first (and `name`/`description` written).
3. Run the affected tests: `python3 tests/run_all.py firmware/model-cycles_OS1.13.syx test_x.py test_modular.py`
   (always `test_modular.py`; before a release the whole suite).
4. Test build for the maintainer's Model:Samples (he runs the Cycles OS on it and only needs the `_cyc-os` file):
   `python3 tools/build.py --in firmware/model-cycles_OS1.13_for-model-samples.syx --out build/smpNN`
   → `build/smpNN_cyc-os.syx`. Test builds are numbered: the last one was **smp47**; the next is smp48.
5. `node tests/check_flasher.mjs firmware/model-cycles_OS1.13.syx firmware/model-cycles_OS1.13_for-model-samples.syx`
   when patches or the manifest changed (the flasher reads `patches/`).

## Architecture in short

- **Core (patch 00)** provides shared services; most patches require it: encoder slots (`SLOT`), SETTINGS key slots,
  LED filter slots, TRACK-view key slots, sound slots (`SSLOT`: load/save of extra parameters), value popups (`OVS`),
  pattern storage for header bytes 40..63, the extended parameter-descriptor table (96 entries) and a **64 KB payload**
  appended to the MAIN OS (copied to RAM at 0x43000000 at boot).
- **Payload slots** (`common.PAY_SLOT`): reverb-fx 0x0000 (24 KB), track-filter 0x6000 (4 KB), control-mode 0x7000,
  pad-mode 0x7800, strings 0x8000, sampler 0xB000, core 0xC000, mono 0xE000.
- **Free memory is nearly gone:** only 2 small unused sprite masks are left in the image (124 B, 104 B). New code goes
  into a payload slot.
- **Extra parameters (k 23..32) are all taken** (attack, strum/glide/noise, Grit sample id, 4 filter params, LFO amount).
  A new p-lockable parameter needs a different approach; a plain setting can go into a free pattern-header byte.
- **Pattern header bytes** (`common.P_*`): 40..45 humanize time, 46..51 humanize velocity, 52 reverb fx, 53 delay fx,
  54 delay speed, 55 groove, 56 strum (legacy), 57 pad tracks, 58 filter 24 dB bits, 59 free, 60..63 signature.
- **Sound record**: free bytes +85, +87 (the others are used by the core, filter, LFO amount, sampler).
- Firmware facts (addresses, structures) are in the generators' docstrings and in Modded-Cycles' `notes/`.

## State and open items (2026-11-22)

- Release **2.3.1** (2026-11-22): 24 dB mode of the track filter (patch 12: FUNC + GATE in the filter mode, stored per
  pattern and track in header byte 58, not in the sound) and less CPU load for the effects, bit-identical sound
  (smp46/47: delay line and chorus ring read through the cached alias, Hall/Room/Plate loops unrolled x4, Hadamard in
  3-instruction butterflies). Measured on hardware: ChDel + Room 1–3 % less load after smp46.
- `tests/prof_fx.py` profiles the effects (instructions, uncached accesses, 16-B lines, time model 1.54 cycles per
  instruction, 15 per line, ~40 per uncached access). Unicorn reports no m68k memory reads; the script computes the
  addresses from Capstone operands.
- Open: whether 24 dB per pattern is enough; filter attack was discussed and postponed.
