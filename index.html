PPPCCC M:C Mods

With version 2.3 this project has more or less reached its final form, and with it I consider my work on it done.

My goal was always to build my personal interpretation of the Model:Cycles and the Model:Samples: the instrument I wanted for my own music, musical and hands-on, good to play live, with as little menu diving as possible. I am happy about everyone who enjoys it too.

Everything here is open: fork it, change it, take it further — I would love to see where others take it. Please understand that I don’t have the capacity to take personal requests or to offer support or other services of that kind. I will try to fix bugs here and there, as far as my time allows.

A big thank-you to all the modders who made this possible with their work and their inspiration (credits).

— PPPCCC

Features

Each feature is one patch; the number is the patch number, the newest come first. “Details” opens the full page with storage, hooks, memory and tests. Choose your combination in the flasher, or name the patches when you build.

Update v2.300 · The core

Most patches build on a small core; the flasher and the build tool add it automatically. It holds what several patches share — gesture and key slots, value popups, pattern and sound storage for extra parameters, a payload area for larger code — and it brings a few improvements of its own:

  • FUNC + DECAY = amp attack on every machine (0 to ~2 s), p-lockable, saved with the sound
  • TRACK + T1…T6 selects the track; T1…T6 alone no longer do
  • FUNC + knob moves in fine steps, like the knob alone
  • Multi-line browser: three names in the small font
  • Scrolling names in the browser
  • Volume and pan as numbers on the main screen
  • RETRIG opens the save menu in the browser (RT=MENU)

Monom: monophonic synth

New v2.3needs core, 15, 16

A 9th machine in the spirit of the SH-101, Minimoog, Pro-One and MS-20: warm and imperfect. Eight waves (SAW, SQR, PWM, S+P, TRI, SYNC, DTN, RING), a timbre control per wave, sub oscillator, drive, glide and noise. Oscillator drift, random detune per note and free-running phases. GATE works as on TONE. Use the track filter (12) as its filter.

Vlvt: string machine

New v2.3needs core, 15

An 8th machine: a string ensemble in the style of a Solina. Two sawtooth layers per note (8′ and 4′), a tone control and a lush three-tap ensemble. It plays the chords of the CHORD machine, plus mono and unison, and can be strummed with patch 06. GATE works as on CHORD.

15

Grit: sampler machine

New v2.3needs core

A 7th machine: a simple sampler in the style of the Model:Samples with six models — CLEAN, SP (26 kHz, 12 bit, drop-sample), LM (28 kHz, 8-bit mu-law), MIRAGE (29.4 kHz, 8 bit), TX16W (33.3 kHz, 12-bit floating point) and MPC60 (40 kHz, 12-bit floating point). Samples come from the +Drive and are chosen in the browser; the waveform shows while you set start and length. Sample locks lock only the sample. Upload samples with Elektron Transfer (Device Config › Transfer: SMP).

Grit, Vlvt and Monom only work together: Vlvt needs Grit, Monom needs Grit and Vlvt.

Why there is no .syx download

A firmware file contains Elektron’s operating system, which I am not allowed to redistribute. This repository only holds my own code: the bytes each patch writes, plus a SHA-256 checksum of the original bytes it replaces. No Elektron code is in here. Where a hook has to move a few original instructions into a patch’s own code, the patch file holds only a placeholder and a checksum; the build copies those bytes from your own firmware file.

You build the firmware from your own copy of the official file — in the flasher or with the build tool. Every single write is checked, and the complete result against a published checksum.

Repository layout

patches/   one JSON per patch (offsets, new bytes, SHA-256 of the
           original bytes) + manifest.json
tools/     build.py (.syx -> .syx), apply_patches.py (image -> image)
docs/      user guide, build guide, technical reference, changelog,
           one page per patch
grooves/   the groove tables (grooves.json)
src/       the generators: readable ColdFire assembler in Python
tests/     the emulator tests (run_all.py)
assets/    title images

You do not need src/ or tests/ to build the firmware. They are here for transparency, and so others can check the work and build on it. See the technical reference.

Build it

⚡ Flasher ⬇ Download all files (ZIP)

The easiest way is the flasher: choose your patches, give it your official firmware file, and flash from the browser. To build on your computer you need Python 3, the official model-cycles_OS1.13.syx from elektron.se — nothing else; the container code is included.

git clone https://github.com/gialloinfuso/PPPCCC-M-S-Mods
cd PPPCCC-M-S-Mods
python3 tools/build.py --in model-cycles_OS1.13.syx \
        --out cycles-mods
# -> cycles-mods_cyc-os.syx

To install only some features, name them; what they need is added:

python3 tools/build.py --in model-cycles_OS1.13.syx \
        --out my-mods mute-solo reverb-fx track-filter

For a Model:Samples you first make the Cycles OS for the Samples with Modded-Cycles’ cross-flash tool, then build from that file. Both are covered in the build guide.

As with any firmware mod: use at your own risk. The start-up menu (hold FUNC at power-on) can always bring back an official OS.
